# 0002: Build the company in public

## Decision

The founder requested that `agentforge-hq/company` become public so we can share
how we work, streamline the organization and use our organizational design as
part of how people discover AgentForge. This replaces the private-company
boundary in [0001](0001-operating-model.md).

Keep the skill and company as separate public repositories. Publish the company
vision, roadmap, function mandates, operating experiments, evidence and lessons
from accepted changes. The company repository retains its existing license;
this decision changes visibility, not reuse rights. Apache-2.0 continues to
apply to the separate skill.

## Operating consequences

- Write active documents and work items for a public audience.
- Preserve the difference between a proposal, an accepted change and a verified outcome.
- Use source-linked operating lessons as a marketing input; publication to other
  channels remains a separate action.
- Keep credentials, personal data, customer data and confidential third-party
  material outside repository history, workflow logs and artifacts.
- Retain role scopes, human review and the existing disabled live-worker policy.

The history and existing workflow outputs were reviewed before the visibility
change. Verification records the resulting GitHub visibility. This decision
does not claim that the worker pilot is running on the live xAI API.
