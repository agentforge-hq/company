# Proposed v0.1 compatibility contract

The job is to help a developer inspect and maintain an installed skill
collection without losing useful instructions or making hidden changes.
The [source brief](source-brief.md) remains a historical proposal. This contract
narrows its extra features to a testable first release. The founder approved the
[Go runtime](../decisions/0003-native-go-runtime.md); the scope choices below are
proposed for review in AF-002.

| Area | v0.1 decision | Owner |
| --- | --- | --- |
| Runtime | Accept native Go, embedded defaults and six build targets without an installed Python runtime. Disclose limited Python syntax checks. | Engineering |
| Scanner | Accept JSON, eager and conditional rules, ancestor scopes and strict mixed duplicate groups. Defer Markdown tables, three-tier totals and 30-line extraction candidates to a demonstrated M2 need. | Engineering |
| Command aliases | Keep `audit`/`scan` and `distill`/`automate-me`. Management previews by default. Defer `--json`, `--audit-rules`, freeze/thaw and universal `--dry-run` aliases until an integration needs them. | Product |
| Score | Keep six configurable SDQS dimensions. Reject silently switching to the brief's four-part score because results would lose comparability. Scores remain structural heuristics. | Product |
| Script and resource checks | Accept Go AST, literal Python flags and explicit references without executing inspected code. Defer shell flags, orphan checks and whole-resource budgets until an M2 defect supplies a regression case. | Engineering |
| Routing evaluation | Accept lexical pairs, optional full matrix and supplied positive/negative cases with abstention. Defer generated prompts to M3. Tuning cases cannot establish independent routing accuracy. | Product |
| Storage | Keep external state, reversible moves, journals and user-selected canonical sources. Reject a mandatory vault without a demonstrated migration benefit. Defer plugin shadows to M2 after verifying harness discovery behavior. | Engineering |
| Export and isolation | Accept portable bundles, explicit metadata losses and documented mappings. Reject unverified flags and Muse paths. Preserve restrictions or require acknowledgment of losses. | Engineering |
| Discovery | Accept requested public search/fetch, pinned quarantine, heuristic inspection and reviewed-fingerprint promotion. Defer marketplace ranking to M4. Exclude automatic compaction before outcome validation. | Product |
| Drift repair | Accept local Git, exported PR/transcript evidence, cause triage and review-only drafts. Defer remote PR mining and generated diffs to M2 after an accepted manual repair. Never weaken instructions to hide a product bug. | Engineering |
| Distillation | Two separate user messages can trigger a draft, not prove an independent recurring task. Promotion requires a held-out M3 task. Three mentions would not establish independence either. | Product |
| Acceptance | Native regressions, OS/toolchain CI, package checks and migration fixtures are engineering evidence. Reject claims of full brief implementation, universal support, security certification or task lift. M2–M3 need user outcomes. | Product |

Evidence is maintained in [release verification](../evidence/release-verification.json),
the [claims register](../evidence/claims.json) and
[field feedback](../engineering/devin-field-feedback.md).

Muse.ai is a cloud target clarified by the founder. Local path mappings for an
unrelated MUSE project are excluded. The original research claims about market
size, universal harness behavior and model gains remain hypotheses.

AF-002 closes after review accepts or changes these explicit scope decisions.
M2 proves one maintenance result; M3 measures actual selection and task outcomes.
M4 tests demand before adding a registry or hosted service. No recurring work
or paid provider calls are enabled by this contract.
