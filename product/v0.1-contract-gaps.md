# Proposed v0.1 compatibility contract

The job is to help a developer inspect and maintain an installed skill
collection without losing useful instructions or making hidden changes.
The [source brief](source-brief.md) remains a historical proposal. This contract
narrows its extra features to a testable first release. The founder approved the
[Go runtime](../decisions/0003-native-go-runtime.md); the scope choices below are
proposed for review in AF-002.

| Area | v0.1 decision | Owner and evidence |
| --- | --- | --- |
| Runtime | Accept the native Go CLI with embedded defaults and six build targets. Do not require Python on installed machines. Disclose the Python syntax-check boundary. | Engineering; merged skill PR 2, runtime decision and release verification |
| Scanner | Accept JSON inventory, eager/conditional rules, ancestor scopes, strict fingerprints and mixed duplicate groups. Defer Markdown tables, three-tier totals and 30-line extraction candidates to M2 only if a real maintenance job needs them. | Engineering; native scan regression cases and installed audit |
| Command aliases | Retain documented `audit`/`scan` and `distill`/`automate-me` aliases. Defer `--json`, `--audit-rules`, freeze/thaw and universal `--dry-run` spellings until an integration demonstrates a need. Current management commands preview by default. | Product; documented CLI help and preview/apply tests |
| Score | Keep the existing six configurable SDQS dimensions. Reject silently replacing them with the brief's four-part score: the numbers would no longer be comparable. Treat either score as a structural heuristic. | Product; public evaluation rubric |
| Script and resource checks | Accept Go AST checks, literal Python flag checks, explicit reference checks and disclosed unverified cases. Defer shell flag parsing, orphan checks and whole-resource budgets to M2 when a missed defect supplies a regression case. | Engineering; linter regressions, no inspected code execution |
| Routing evaluation | Accept lexical pairs, optional full matrix and user-supplied positive/negative cases with abstention. Defer generated prompts to M3; prompts used to tune the tool cannot also establish independent routing accuracy. | Product; saved 12-case regression set, no actual model-routing claim |
| Storage | Keep external state, reversible cold moves, restore journals and a user-selected canonical source. Reject a mandatory vault for v0.1: another source location would require migration without demonstrated benefit. Defer plugin shadows to M2 after a documented harness proves how they affect discovery. | Engineering; no-overwrite, lock, rollback and legacy-journal tests |
| Export and isolation | Accept portable bundles, explicit metadata losses and documented target mappings. Reject unverified isolation flags, including speculative Muse paths. Preserve tool restrictions or require acknowledgment when export loses them. | Engineering; export tests and harness topology |
| Discovery | Accept explicitly requested public search/fetch, commit-pinned quarantine, heuristic inspection and reviewed-fingerprint promotion. Defer marketplace ranking to M4; automatic compaction stays out of v0.1 because it changes third-party instructions before outcome validation. | Product; fetch, archive, fingerprint and promotion tests |
| Drift repair | Accept local Git, exported PR/transcript evidence, cause triage and review-only drafts. Defer remote PR mining and generated repair diffs to M2 after one manual repair is accepted. Never hide a product bug by weakening instructions. | Engineering; drift regressions and AF-003 |
| Distillation | Keep repeated eligible commands in two separate user messages as a draft threshold. Reject calling that proof of a recurring independent task; promotion requires a representative held-out task in M3. Three mentions alone would not establish independence either. | Product; role-aware transcript tests and manual review |
| Acceptance | Accept 86 native regressions, OS/toolchain CI, package smoke checks and migration fixtures as engineering evidence. Reject a claim of full brief implementation, universal harness support, security certification or task lift. M2–M3 require observed user outcomes. | Product; release verification and claims register |

Muse.ai is a cloud target clarified by the founder. Local path mappings for an
unrelated MUSE project are excluded. The original research claims about market
size, universal harness behavior and model gains remain hypotheses.

AF-002 closes after review accepts or changes these explicit scope decisions.
M2 proves one maintenance result; M3 measures actual selection and task outcomes.
M4 tests demand before adding a registry or hosted service. No recurring work
or paid provider calls are enabled by this contract.
